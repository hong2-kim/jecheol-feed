# 카드·장면 검수 기준 (2026-10-28 사용자가 정함)

원칙은 PROMPT.md "화면은 사진 중심, 글씨는 보조". 글을 자세히 읽기 전에 사진만 보고도 주제를 알아야 한다. 다만 **꼴마다 기준이 다르다.** 모든 장에 같은 사진 비율을 강제하면 비교·설명 장이 망가진다(사용자). 사진 수가 아니라, 내용을 이해하는 데 필요한 사진이 알맞게 놓였는지를 본다.

## 검수는 세 단계

| 단계 | 언제 | 무엇을 | 걸리면 |
|---|---|---|---|
| 1. 설계도 검사 | `python video/build.py 설계도` (매일 실행이 커밋 전에) | 칸 누락·글 길이, **사진 없는 소식 장**, hero 정보 줄·제목 줄 수 | "꼭 고쳐 주세요"면 고치거나 그 장을 보류 |
| 2. 사진 적합성·출처 (`scripts/contentcheck.py` → `scripts/gate.py`) | 같은 때 | 사진 이용 조건(`photo_rights`), 사진에 찍힌 것(`shows`)과 글의 이름, `match`, 참고 사진 딱지(`ref`) | 차단 / 확인 필요(사람 승인) / 참고 |
| 3. 그린 뒤 검수 (`video/produce.py` `render_cards`) | 카드를 그림으로 찍은 직후 | 제목 크기·사진 넓이·빈 여백·빈 띠, **글자 겹침·화면 밖 잘림**, 단어 하나가 화면을 차지 | 꼭 고칠 것: 그 카드 묶음을 보내지 않음. 확인 필요: 기록에 남겨 사람이 봄 |

컴퓨터는 사진 속을 알아보지 못한다. "사진이 내용 이해에 도움이 되는가"는 2단계의 `shows`·`match` 대조로 단서만 잡고, 나머지는 **확인 필요**로 넘겨 사람이 본다.

## 소식 단위 보류와 발행 안정성 (2026-10-28 사용자)

사진 한 장 문제로 하루치 전체가 멈추지 않게, **문제 있는 소식만 빼고** 나머지를 그대로 만든다. 빼는 단위는 장이 아니라 **소식**이다(한 소식이 여러 장이면 함께 빠져 일부만 남아 왜곡되지 않게). 권리를 확인하지 않은 사진이나 오류가 있는 장은 절대 그대로 내보내지 않는다.

| 상황 | 처리 |
|---|---|
| 정상 소식 | 그대로 제작·발행 |
| 디자인 문제(제목·사진·여백·글자 겹침·작은 글자) | 큰 제목 장은 자동으로 작게(`compact`) 고쳐 다시 그려 재검수 → 그래도 걸리면 그 소식만 보류 |
| 사진 누락 | 복구 절차(실제 사진 → 보도자료·미디어센터 → 다른 사진·시각 자료 → 레이아웃)를 거쳐 `photo_search` 에 적으면 그 소식만 보류. 안 적으면 설계도 검사에서 "꼭 고쳐 주세요" |
| 사진 이용 조건 확인 전(등록부 '확인 필요') | 그 소식만 '확인 필요'로 보류 |
| 사실·사진 일치 오류, 출처 불명 사진(차단) | 그 소식만 발행 차단 |
| 첫 소식이 걸림 | 남은 소식이 2개 이상이고 새 맨 앞 소식에 `lead`(썸네일·표지·게시글 첫 줄·유튜브 제목)가 있으면 그것으로 다시 꾸며 **나머지를 보냄**. 아니면 전체 보류 |
| 남은 장 부족, TOP5, 소식을 깔끔히 떼어 낼 수 없음, 표지·게시글 자체 오류, 새 꼴인데 장의 `news` 가 빠짐 | 지우지 않고 **전체 보류** |

**소식 단위(`news`)**: 소식마다 제목·요약·게시글 문단·썸네일 한 줄·태그·출처·사진 표기를 따로 갖고, 엔진이 그것으로 게시글·제목·목록을 짠다. 소식을 빼면 그 소식의 칸만 빠지고 남은 소식 글은 한 글자도 바뀌지 않는다(시험으로 확인). 예전 설계도(`news` 없음)는 번호 문단·쉼표·가운뎃점 단위로만 떼어 내고, 한 토막에 두 소식이 섞여 있으면 지우지 않고 전체 보류한다(요약만은 남은 소식의 썸네일 줄로 새로 쓴다).

자동으로 맞추는 것: 쪽 번호(`n / 전체`), 표지 '뉴스 N'(소식 수)과 목록, 썸네일 목록과 '뉴스 N', 게시글 번호 문단·첫 두 줄·'N가지'·출처 줄, 제목·유튜브 제목·요약, 태그·사진 표기.

보고: 제작 기록(`dist/results.json` 의 `held`), 발송 때 텔레그램 "✂️ 뺀 장과 까닭" + 뺀 장의 사진 자리를 빨간 테두리로 표시한 검수 시트, `state/review.json` 의 `held_cards`(다음 제작 때 다시 봄). 보내기 전 검수(`gate.py`)는 뺀 장을 가리키는 결과만 '참고'로 낮춘다.

## 사진 복구 절차는 지금 '기록·검수'다 (자동 재탐색 아님, 2026-10-28 확인)

- **지금 되는 것**: 사진 찾기 함수는 있다 — `scripts/photos.py` 의 `tour`·`commons`·`openverse`·`pexels`·`sheet`·`get`, `scripts/news.py` 의 `press`·`text --images`. 하지만 이것들은 **매일 아침 Claude(클라우드 루틴)가 설계도를 쓰는 동안 직접 부르는 도구**다. 제작(`produce.py`)·검수(`build.triage`, `gate.py`)·깃허브 자동 작업은 사진을 다시 찾지 않는다.
- `photo_search` 는 Claude 가 네 단계를 해 본 결과를 적는 **기록 칸**이고, 엔진은 네 칸이 다 적혔는지만 본다(적혔으면 그 소식만 보류, 아니면 "꼭 고쳐 주세요"). 실제로 찾았는지·내용이 맞는지는 엔진이 확인하지 못한다.
- 복구 성공 조건(루틴 안에서): 찾은 사진을 열어 보고(`photos.py get` + 확인) `shows`·`match` 를 적었고, 이용 조건이 '사용 가능'이거나 `terms.ok` 다. 실패: 네 단계 모두 맞는 사진이 없거나 권리가 확인 전.
- **추가 구현 범위(아직 없음)**: ① 보류된 소식마다 그 이름으로 `commons`·`openverse`·`tour`·`news.press` 를 자동으로 돌려 후보 모음 시트를 만들어 보류 알림에 붙이는 `scripts/photo_recover.py` ② 다음 날 루틴 시작 때 그 후보를 Claude 가 열어 보고 고르게 하는 규칙. 사진이 글과 같은 대상인지는 사람이 봐야 하므로(규칙 "shows 를 적기 전에 사진을 반드시 열어 본다") **후보를 자동으로 넣어 발행하지는 않는다.**

## 썸네일 참고 사진 표시 (2026-10-28 사용자)

- 썸네일 사진의 `match` 가 `같은 종류`·`분위기`면 사진 오른쪽 위에 작은 딱지(40px, 휴대폰에서 약 14pt)가 붙는다. `ref` 를 적으면 그 말("참고 사진 · 실제 제품 아님"), 없으면 "참고 사진".
- `match: 정확` 이거나 적지 않은 사진에는 붙지 않는다.

- 트렌드 카드 본보기(`video/examples/8-trend.json`)는 아직 예전 꼴이다(예전 꼴 처리로 돌아감). 모음 카드 본보기의 장은 hero 규칙 전 모양이다.

## 휴대폰에서 읽히는 글자 (2026-10-28 사용자)

- 카드(1080×1350)는 휴대폰(가로 약 390pt)에서 0.36배로 보인다. 26px 는 약 9.4pt, 30px 는 약 10.8pt.
- 모든 장의 글자는 **26px 이상**이어야 한다(그린 뒤 검수가 막음). 출처 줄은 28~30px, 참고 사진 딱지 28px, 값표 메모·비율 그림 설명 26px 로 올렸다.
- 출처 줄은 짧게(매체 이름·날짜), 자세한 출처는 게시글 끝 `출처:` 줄로.
- 시험: 식빵·3.5배·오레오 장을 가로 390px 로 줄여 확인(`(저장소 밖, 이 컴퓨터의) 시안-10-28/식빵카드/모바일-390.png`).

## 발견형·내레이션 영상 사진 (2026-10-28 사용자 승인)

- 음식 사진: 가로 사진도 칸을 꽉 채워 크게(발견형 장면 1100px·표지 1240px = 화면의 57~65%, 예전 통째로 약 37%; 내레이션 사진 칸 1080×890 을 꽉). 가장자리만 잘리고 비율은 그대로, 핵심 위치는 `pos`.
- 전체가 중요한 사진(포장·포스터·안내문): `"fit": "contain"` / `"kind": "poster"` 면 예전처럼 통째로. 흰 바탕 상품 사진은 내레이션에서 자동으로 흰 칸.
- 확대 효과는 넣지 않았다(필요할 때만 `fit`·설계도로).
- 시험: 10-28·10-24 발견형, 10-25 내레이션을 예전·새 방식으로 그려 견줌(`(저장소 밖, 이 컴퓨터의) 시안-10-28/발견형영상/전후비교.jpg`).

## 바뀐 것 (`cards-photo-first` 가지, 커밋 전)

- `video/build.py`: hero 틀(사진 중심, A/B 자동 선택, 상품 흰 판, 비율 그림), 참고 사진 딱지(hero·소식 장·숫자 장·표지·비교 칸), 사진 없는 소식 장 차단, 그린 뒤 검수(`LAYOUT_PROBE`, `layout_checks`, `layout_problems`, `empty_band`).
- `video/cards.css`: hero·딱지·비율 그림 모양.
- `video/produce.py`: 카드 단위 보류(`triage`), 그린 뒤 검수·자동 수정·그 장만 빼고 다시 그리기, 확인 필요 출력.
- `video/publish.py`: 뺀 장 알림·검수 시트, gate 에 뺀 장 번호 전달. `scripts/gate.py`: 뺀 장 결과를 참고로.
- `video/base.css`, `video/voice.py`: 영상 음식 사진 크게(`fills`, `keep_whole`).
- `docs/photo-rights-press.md`: 회사 보도자료 사진 판단 기준과 동서식품 검토.
- `scripts/contentcheck.py`: 상품 이름 글 + 같은 종류 사진이면 `ref` 딱지가 있을 때만 참고로 낮춤.
- `sources.json` `photo_rights`: 동서식품 추가(확인 필요, 약관 제13조).
- `PROMPT.md` "화면은 사진 중심", "정확한 사진이 없을 때", `rules/daily/cards.md` hero·사진 없는 장 규칙.
