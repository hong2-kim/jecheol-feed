### 남은 문제·한계
- 판정은 낱말 기반 단서다. 같은 음식을 전혀 다른 이름으로 부르면(`SYNONYMS` 에 없는 말) 놓칠 수 있고, 흔한 브랜드 이름(GS25)만 겹쳐도 약하게 잡힐 수 있다.
- `dates` 칸은 앞으로 루틴이 적어야 생긴다. `--fetch` 없이 `build.py` 는 기사를 열지 않는다(시간 절약).
- (3단계 안정화, 2026-10-23 사용자 요청) 빠진 날짜 알림은 **2026-10-24 이후 설계도에만** 낸다(`DATES_FROM`). 지난 설계도는 dates 가 없어도 알리지 않고 중복 확인용 참고 자료로만 쓴다. 오래된 기사를 새 소식처럼 쓴 것 같은 실제 문제는 `--fetch` 로 그대로 잡는다. 지난 기록을 고치거나 날짜를 추정해 채우지 않았다. 새 콘텐츠는 출처마다 발행일이 없으면 "추정하지 말고 기사에서 확인해 적어 주세요"로 알린다.
  - 시험: 10-20~10-23 설계도 16개 → dates 알림 0건. 10-22 인천(`--fetch`) → 2023·2014년 기사 경고 유지. 10-24 날짜 사본(dates 없음) → "dates 칸이 없어요", (dates 일부) → "출처 3곳의 발행일 없음"·"확인일 없음".
- 알림만 하고 막지 않는다. 막는 것은 5단계(발송 전 검수)에서 정한다.
- inbox 후보 수백 건을 미리 한꺼번에 거르는 명령은 만들지 않았다(`check` 는 후보 하나씩). 필요하면 6단계에서.
- 3단계 파일은 GitHub 에 올리지 않았다.
