# 소재(사진·영상) 고르는 순서와 출처·이용 조건 — 보류 중인 새 규칙

> 상태: **보류(승인 전)**. 2026-10-19 사용자가 소재 우선순위와 회사 상품 이미지 기준을 정했다. 매일 실행은 아직 이 파일을 읽지 않는다(`rules/_hold/`). 지금 매일 규칙(`PROMPT.md` "비공개 사진 보관함", `rules/daily/voice.md` 37행 "회사 공식 사진")과 다른 점은 아래 "지금 규칙과 다른 점".
> 도구: `scripts/media.py`(목록·찾기·검사), 조건 표 `video/sources.json`, 기록 `docs/stage5-dinner-shorts.md` 6절.

## 고르는 순서

1. **사용자가 준 음식 사진·영상** — 비공개 보관함 `jecheol-photos`(428개) + 텔레그램으로 보낸 것(`myphotos/index.json`). 이 컴퓨터의 `내-음식-사진`(421개)은 보관함과 같은 파일이다(sha256 으로 모두 맞춤). **다시 받거나 따로 모으지 않는다.**
   - 찾기: `python scripts/media.py find 떡볶이`(음식 이름) 또는 `find 분식`(갈래). 안 쓴 것·쓸 수 있는 것이 먼저 나온다.
   - 갈래 21개: 분식 / 라면 / 중식 / 버거·핫도그 / 치킨·튀김 / 돈가스·일식 / 피자·파스타·양식 / 면·국수 / 만두 / 생선구이 / 찌개·탕·전골 / 회·해산물 / 고기구이 / 족발·보쌈·수육 / 전·부침 / 밥·한 상 / 빵·디저트 / 과일 / 시장·가게 / 음료·술 / 기타.
   - 설계도에는 보관함 주소(`vault:photos/…`)를 적는다. 이 컴퓨터에서 만들 때만 `vault:내-음식-사진/…`를 쓸 수 있다(클라우드에서는 못 읽음).
2. **한국관광공사** — `scripts/photos.py tour 키워드`. 맞는 사용자 사진이 없을 때.
3. **편의점·마트·식품 회사 공식 상품 이미지** — 상품 모습이 꼭 필요한 편의점·마트·가공식품 콘텐츠에서만 검토. **이용 허락이 확인되기 전에는 자동 게시에 쓰지 않는다.**
4. 위가 안 되면 **자체 그래픽**(가격표·예산·순서·고르기 카드)이나 쓸 수 있는 다른 사진(위키미디어 CC0·퍼블릭 도메인, Pexels)으로 해결한다.

## 사용자 사진: 폴더에 있다고 바로 쓰지 않는다

`python scripts/media.py catalog` 가 만드는 목록(`내-음식-사진/_목록.json`, `_목록.md`, 공개 저장소에 넣지 않음)에 항목마다 `status` 와 까닭(`why`)이 있다.

| status | 뜻 | 쓰는 법 |
|---|---|---|
| 사용 가능 | 음식 이름 확실, 사람 표시 없음 | 내용은 문제없음. **게시는 권리 '확인'일 때만**. 출처 줄 필요 없음 |
| 사용 가능(조건) | 상표·가게 이름이 보일 수 있음(맥도날드·KFC 등) | 그 회사 이야기일 때만, 협찬처럼 보이지 않게 |
| 검토 필요 | 무슨 음식인지 확실치 않음(`ask`) / 사람 손·몸이 보임(`careful`) / 폴더 이름과 보관함 이름이 다름 / 콜라주 | `ask`·이름 다름은 **사용자에게 묻기 전에는 쓰지 않는다**(검사가 막음). `careful` 은 크게 열어 얼굴이 없을 때만 |
| 사용 끝 | 텔레그램 사진 중 이미 쓴 것 | 다시 쓰지 않는다 |

- **권리(`rights`)는 내용(`status`)과 따로 본다**(2026-10-19 사용자가 정함). 인스타그램에서 가져왔다는 것만으로 직접 찍은 사진으로 보지 않는다. **직접 찍었거나 사용 권한이 확인된 것(`rights: 확인`)만 상업용 콘텐츠(게시)에 쓰고**, 출처·권리가 불분명한 것은 보류한다.
  - 확인: 텔레그램으로 보낸 사진(직접 찍어 보낸 것, `rules/when/myphotos.md`), 사용자가 `_검토목록.csv` 에 '내가 찍음: 예'를 적은 것.
  - 미확인: 인스타그램에서 옮긴 421개, 대화로 보낸 7개(직접 찍었는지 확인 전).
  - 검사(`media.py check`)는 권리 미확인 사진을 게시용 설계도에서 막는다. 비공개 샘플(`"sample"`)은 알림만 한다.
- **폴더 파일 이름은 사용자가 붙인 이름이라 갈래를 나눌 때 참고한다**(2026-10-19). 다만 보관함 이름과 다르면(52개) 자동으로 확정하지 않고 검토로 둔다. 이름이 같은 것을 먼저 쓴다.
- 사용자가 확인할 표: `내-음식-사진/_검토목록.csv`(파일번호·현재 이름·의심되는 이름·갈래·보류 이유). '음식 이름 확인'(보관함 / 폴더 / 새 이름)과 '내가 찍음(예/아니오)'을 채우고 `media.py catalog` 를 다시 돌리면 반영된다.
- 태그: `동작`(끓이기·자르기 등, 대사와 맞출 때), `술`(저녁 영상에는 쓰지 않음), `20xx년`(오래된 사진: 지금 값·영업 정보로 쓰지 않음).
- 쓴 뒤 보관함 `index.json` 의 `used` 에 적는 규칙은 지금과 같다(`PROMPT.md`).

## 회사 공식 상품 이미지 (CU·GS25·세븐일레븐·이마트·롯데마트·식품 제조사)

2026-10-19 각 공식 홈페이지를 직접 확인한 결과(`video/sources.json` 의 `companies`):

| 회사 | 확인한 것 | 판단 |
|---|---|---|
| CU | 하단 "COPYRIGHT © BGFretail ALL RIGHT RESERVED."만, 재사용 안내 없음 | 허락 없음 → 검토 대상 |
| GS25 | "Copyright ⓒGS Retail. All rights reserved."만 | 허락 없음 → 검토 대상 |
| 세븐일레븐 | "COPYRIGHT 2014 KOREA SEVEN CO, LTD. All Rights Reserved."만 | 허락 없음 → 검토 대상 |
| 이마트(SSG) | 이용약관 제26조: 사전 승낙 없이 영리 목적 복제·배포 금지 | 허락 필요 |
| 롯데마트 | 이용약관 제16조: 사전 승낙 없이 영리 목적 복제·배포 금지 | 허락 필요 |
| 식품 제조사 | 확인한 곳 없음 | 회사마다 따로 본다 |

- 보도자료 사진은 기사 보도용으로 배포한 것이다. 쇼츠·블로그 재사용 허락으로 보지 않는다.
- **출처 표시만으로 허락이 되지 않는다.** 홍보 효과가 있어도 마찬가지다.
- 쓰려면 설계도 `assets` 에 적는다(검사가 빠진 것을 막음):
  ```
  {"url": "<원본 이미지 주소>", "tier": 3, "company": "CU", "src": "CU 홈페이지 상품 목록",
   "product": "고메김치우동한그릇", "price": 4500, "size": "1인분", "page": "<상품 페이지 주소>",
   "checked": "2026-10-19", "fact": "udon",
   "permission": {"how": "서면(이메일)", "who": "보낸 곳", "date": "받은 날"}}
  ```
  - 상품명·가격·용량이 페이지와 같은지, 이미지가 그 상품인지 본다. 가격은 `facts` 의 근거와 맞아야 한다(`fact`).
  - `permission` 이 없으면 **자동 게시용으로 확정하지 않는다**(검사가 "검토 대상"으로 막음). 허락은 사용자가 회사에 직접 받는다(CU 는 홈페이지 "제휴/광고 문의").
  - 게시글에 `product_note`(이미지 출처·확인 날짜·"값은 점포마다 달라요")를 적는다.
- **협찬·제휴를 받은 것처럼 쓰지 않는다.** "협찬", "제공받", "제휴", "공식 파트너", "공식 추천" 등은 검사가 막는다("협찬 아님"처럼 아니라고 밝히는 말은 된다). 진짜 협찬이면 사용자가 정하고 `"sponsored": true` 와 유료 광고 표시를 따로 한다.
- 허락이 없으면: 가격표 카드(상품명·용량·값·합계)로 보여 주고, 사진은 사용자 사진에 "사진은 예시예요" 표시.
