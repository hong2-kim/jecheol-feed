# 텔레그램 [고쳐서 다시] 요청 고치기 (2026-11-06)

사용자가 밖에서 텔레그램으로 "고쳐서 다시"를 누르거나 시안 메시지에 답장하면 `scripts/tg_actions.py` 가 `requests/fix-영상id.json` 을 남긴다.
고치기 루틴(바로)이나 다음 아침 매일 실행(`PROMPT.md` 순서 0)이 이 규칙대로 고친다. **사람에게 묻지 않고 끝까지 한다.**

## 요청 파일

```json
{"rid": "2026-11-06-10-voice", "spec": "videos/2026-11-06/10-voice.json", "status": "open",
 "reasons": ["[확인] 이력: …"], "held_cards": [{"no": 3, "reasons": ["…"]}], "note": "사용자가 답장으로 적은 고칠 점(없을 수 있음)", "at": "…"}
```

## 순서

1. `status` 가 `open` 인 요청만 고친다. 오래된 것부터.
2. `note` 가 있으면 사용자가 직접 적은 요청이다. 그대로 따른다. 사실과 다른 내용을 쓰라고 하면 확인한 사실만 쓰고 보고에 적는다.
3. `reasons`·`held_cards` 는 보내기 전 검수가 걸린 까닭이다. 그 콘텐츠의 `rules/` 파일과 `PROMPT.md` 의 해당 절을 다시 읽고 까닭을 없앤다.
   - 이력(반복 의심·겹침): 앞선 콘텐츠와 다른 점(새 숫자, 새 지역, 새 관점)이 보이게 제목·첫 장면·요약을 바꾼다. 다르게 만들 거리가 없으면 그대로 두고 `status: "kept"` 로 적는다(사용자가 시안을 보고 승인할 수 있다).
   - 사진 확인·권리: `PROMPT.md` 의 사진 절대로 다른 사진을 찾거나 `review_sheet.py` 로 시트를 만들어 실제로 열어 보고 `review.photo_sheet` 를 적는다.
   - 길이: 내레이션·장면을 줄여 기준 안에 넣는다(배속을 고정하지 않는다).
   - 쉼표 발음이 어색하다는 요청이어도 전체 나레이션 속도를 바꾸거나 정상 문장을 고치지 않는다. 걸린 문장의 원인부터 보고, 그 문장만 고친다(2026-11-08 사용자).
4. 그 콘텐츠의 검사(`python3 video/build.py 설계도` 의 "꼭 고쳐 주세요" 0건)와 `python3 scripts/gate.py 설계도` 를 돌린다. 통과하지 못해도 고칠 수 있는 만큼 고친 뒤 올린다(자동 작업이 다시 '승인 전 시안'으로 보내 사용자가 정한다).
5. 요청 파일에 `status: "done"`(또는 `kept`), `done_at`, `summary`(무엇을 고쳤는지 한두 문장)를 적는다. 설계도의 `review` 칸은 건드리지 않는다.
6. 고친 설계도와 요청 파일만 커밋해 `python scripts/safe_push.py` 로 `main` 에 올린다(거부되면 `--branch claude/…`, 막히면 억지로 올리지 않는다). `videos/` 가 바뀌면 자동 작업이 다시 만들어 텔레그램으로 보낸다.
